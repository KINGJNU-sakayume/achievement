# 업적 라이브러리

꾸준히 하고 싶은 일을 기록하면, 조건을 채운 업적이 저절로 쌓이는 개인 기록장입니다.
달리기·독서·저축처럼 카테고리별로 기록을 남기고, 진열장에서 모은 업적을 둘러볼 수 있습니다.
기본으로 카테고리 99개(피트니스·건강·영양·학습·마음 챙김·여행·문화생활·창작·커리어·재정·기술·사회활동·관계·생활)와
업적 1410개가 들어 있고, 업적은 얼마든지 직접 만들거나 고칠 수 있습니다.

- **홈** — 카테고리별 기록, 연속 기록, 다음 목표
- **기록** — 날짜별 기록과 업적 달성 기록, 달력, 검색
- **업적** — 업적 목록과 편집 (조건 빌더, 실시간 미리보기)
- **진열장** — 모은 업적, 대표 업적, 카테고리별 진행률

설치형 웹앱(PWA)이라 휴대폰 홈 화면에 추가해 쓸 수 있고, 시스템 설정에 따라 다크 모드로 바뀝니다.

## 시작하기

Node.js 18 이상이 필요합니다.

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173/achievement/)
npm test         # 업적 엔진·저장 형식·기본 업적 목록 테스트 (Vitest)
npm run build    # 배포용 빌드 → dist/
npm run catalog:snapshot  # 기본 업적 목록을 바꿀 때 (docs/achievement-system.md 8장)
```

`main` 브랜치에 푸시하면 GitHub Actions가 테스트와 빌드를 거쳐 GitHub Pages에 배포합니다
(`.github/workflows/deploy.yml`).

## 데이터는 어디에 저장되나요?

모든 기록과 업적은 **이 브라우저의 localStorage에만** 저장됩니다. 계정은 없습니다. Life Hub를 연결해도 기록은 보내지 않고, 설정에서 켠 기기만 보드용 요약(아래 「보드 타일」)을 올립니다.

- 브라우저 데이터를 지우거나 다른 기기에서 열면 기록이 보이지 않습니다.
  오른쪽 위 **설정 → 백업 파일 받기**로 JSON 백업을 받아 두고, 같은 화면에서 불러올 수 있습니다.
- 사진은 저장 전에 자동으로 줄여서(긴 변 1280px, JPEG) 저장 공간을 아낍니다.
  브라우저 저장 공간(보통 5MB 안팎)이 가득 차면 화면 위에 안내가 뜹니다.
- 여러 탭을 열어 두어도 변경 내용이 서로 맞춰집니다.
- 이전 버전(저장 형식 v1)의 데이터는 처음 열 때 자동으로 옮겨집니다. 자세한 내용은 아래 문서를 참고하세요.

## Life Hub로 기록 제안 받기 (선택)

Claude에게 "오늘 한강에서 5km 뛰었어"처럼 말하면, Claude가 [Life Hub](https://github.com/KINGJNU-sakayume/life-hub)에 **기록 제안**을 남기고 이 앱이 그것을 받아 옵니다.

- **설정 → Life Hub** 섹션의 `Life Hub 연결`로 한 번 연결합니다(배포된 주소에서만). 이 앱은 `achievement:inbox` 권한만 받아 자기 제안만 읽습니다.
- 제안은 화면 위에 "Claude가 제안한 기록"으로 나타납니다. **확인**을 누르면 평소의 기록하기 화면이 제안 내용으로 채워져 열리고(업적 미리보기 포함), **저장**해야 기록됩니다. 카테고리 이름이 정확히 맞지 않으면 직접 고릅니다.
- **거절**하면 기록은 바뀌지 않고 Life Hub에 거절로 알려집니다. 제안으로 저장한 기록은 ID가 `lh_`로 시작해, 저장 결과를 기록 자체에서 다시 알 수 있습니다.
- **새 업적 제안**: "러닝 누적 100km 업적 만들어줘"라고 하면 업적 제안(이름·난이도·조건: 횟수/누적/연속/태그/태그 횟수·카테고리)이 오고, **추가**를 누르면 내 업적에 들어갑니다(ID `lh_…`). 카테고리를 못 찾으면 업적 관리에서 직접 만듭니다.
- **Claude 대화 카드에서 승인**한 기록·업적은 앱을 열 때 바로 저장됩니다. 단, 카테고리 이름이 내 카테고리 하나와 **정확히** 같을 때만이고(업적은 카테고리가 없어도 됨), 아니면 위 제안 목록에서 확인합니다. 설정 → Life Hub의 `Claude에서 승인한 기록은 바로 반영`(기본 켜짐)으로 끌 수 있습니다.
- 카드의 카테고리 고르기를 위해 내 카테고리 이름 목록(id·이름·최상위 이름)을 Life Hub에 공유합니다. 기록 내용은 보내지 않습니다.
- 기록과 업적 정의는 지금처럼 이 브라우저에만 저장됩니다. 서버에 가는 것은 제안, 카테고리 이름 목록, 그리고 켰을 때만 보드용 요약뿐입니다.

## 보드 타일 (선택)

[Life Board](https://github.com/KINGJNU-sakayume/board)에 올릴 **타일 두 개**의 목록을 Life Hub에 올립니다. 최근 흐름만 보여 주려고 "이번 주 몇 개" 같은 통계는 만들지 않았습니다.

| id | 이름 | 모양 | 크기 (처음) | 처음부터 보임 | 데이터 |
|---|---|---|---|---|---|
| `recent` | 업적 · 최근 취득 | type·line | 1x1, 2x1 (2x1) | 예 | 취득일이 가장 늦은 업적의 이름, `등급 · 카테고리 · 11/5` |
| `trophy` | 업적 · 트로피 칸 | type·cells | 2x1, 4x1 (2x1) | 예 | 위 업적이 속한 카테고리의 업적 칸과 취득한 칸 수 |

- **고르는 규칙**: 같은 날 취득이 여럿이면 기록으로 달성한 업적 → 높은 등급 → id 순입니다. 날짜는 업적이 달성된 날(기록한 날짜)이라, 지난 날짜로 기록을 입력하면 그 업적은 입력한 날이 아니라 달성된 날짜로 정렬됩니다. 미래 날짜는 제외합니다. 트로피 칸은 그 카테고리에 **직접 속한** 업적만 세고(하위 카테고리 제외), 칸이 60개를 넘으면 타일을 보내지 않습니다.
- **보내는 것**: 업적 이름·등급·카테고리 이름·달성 날짜, 카테고리의 칸 수와 취득 수. **보내지 않는 것**: 기록(값·단위·메모·태그·사진), 기록 ID, 아직 달성하지 않은 숨김 업적(이름은 물론 칸 수에도 세지 않습니다). 취득한 것이 없으면 타일 없이 빈 목록을 보냅니다. 표지 이미지는 없어서 이미지 주소와 포인트 색도 보내지 않습니다.
- **언제 올리나**: 켜 둔 기기에서 업적이 바뀔 때, 마지막 시도로부터 10분이 지났으면 바로, 아니면 10분이 찬 뒤 한 번 올립니다(10분에 한 번 이하, 실패한 시도도 같은 간격). 내용(`generated_at` 제외)이 마지막에 올린 것과 같으면 올리지 않지만, 앱을 열거나 화면이 다시 보일 때 마지막 성공이 하루보다 오래됐으면 같아도 한 번 올립니다(보드의 '오래됨'은 14일). 앱이 닫혀 올리지 못한 변경은 다음에 열 때 올립니다. 올릴 것이 있다는 표시와 마지막 성공은 이 브라우저에만 저장합니다.
- **어느 기기에서**: 설정 → Life Hub의 **'이 기기에서 보드에 올리기'**(기기별, 기본 꺼짐)를 켠 기기에서만 올립니다. Life Hub에는 앱마다 최신 목록 하나만 남아서 두 기기가 번갈아 올리면 서로 덮으니 한 기기에서만 켜세요. 연결하지 않았거나, 기록도 취득한 업적도 없으면 올리지 않습니다.
- **다시 연결이 필요한 경우**: 이 기능 전에 연결한 기기는 권한(`achievement:board`)이 없어, 켜고 처음 올릴 때 Life Hub가 거절합니다. 이때 연결은 끊지 않고 설정에 "보드에 올리려면 Life Hub에 다시 연결"이 나옵니다. **다시 연결**을 한 번 누르면 됩니다(이 앱을 배포한 뒤 기존 사용자는 한 번 필요).
- **코드**: 목록은 `src/board/buildBoardTiles.js`(입력만으로 결과가 정해지는 순수 함수), 올리는 규칙은 `src/board/upload.js`, 예시 출력은 [board/sample.json](board/sample.json)(지어낸 값)입니다. 테스트는 board의 `js/schema.js` 복사본(`src/board/vendor/schema.js`)으로 규격을 확인합니다.

## 업적은 어떻게 달성되나요?

업적의 달성 여부와 진행도는 저장하지 않고, 기록 전체를 바탕으로 매번 다시 계산합니다.
그래서 지난 날짜로 기록을 남기거나, 기록을 고치거나 지워도, 업적을 나중에 만들어도 결과가 항상 맞습니다.

- 업적의 카테고리에는 **하위 카테고리 기록까지** 포함됩니다. 카테고리가 없는 업적은 모든 기록을 셉니다.
- 조건 종류: 첫 기록, 횟수, 기록한 날 수, 연속 기록, 매주·매달 꾸준히, 누적 합계, 한 번에 넘기기, 하루 합계,
  한 주·한 달·한 해 합계, 태그, 태그 모으기, 여러 카테고리에 기록, 여러 카테고리 합산(예: 3대 중량), 조건 묶기,
  다른 업적 기반(메타, 등급별로 세기 가능), 직접 체크. 횟수·날 수·연속 기록에는 "하루 2L 이상"처럼 기준 값을 붙일 수 있습니다.
- 단위가 다른 기록은 환산할 수 있으면 자동으로 바꿔 더합니다(m→km, ml→L, 분→시간, 만원→원, 쪽→페이지, 보→걸음 …).
  기본 업적은 카테고리마다 단위를 하나만 써서, 단위 없이 적은 숫자도 헷갈리지 않습니다.
- 등급은 브론즈 · 실버 · 골드 · 플래티넘 · 다이아몬드 다섯 단계입니다.

**기록하기** 화면은 카테고리 업적이 쓰는 단위를 미리 채우고(`5km`, `1,000`처럼 적어도 됨), 업적에 반영되지 않는 단위를 경고하며,
저장하면 달성할 업적과 가까워지는 업적을 입력하는 대로 보여 줍니다.

기본 업적 목록이 바뀌면 기존 사용자의 데이터에도 새 카테고리와 업적이 더해집니다. 직접 고친 업적, 지운 업적과 카테고리는 그대로 둡니다.

규칙 전체와 기본 목록, 변경 내역은 [docs/achievement-system.md](docs/achievement-system.md)에 정리되어 있습니다.

## 구조

```
src/
├── App.jsx                      # 상단 바, 모바일 탭 바, 라우트
├── context/
│   ├── AppContext.jsx           # 앱 상태(reducer), 저장, 업적 계산 결과, 달성 알림
│   ├── UIContext.jsx            # 어디서나 여는 시트: 기록하기, 업적 상세, 설정
│   └── ToastContext.jsx         # 알림(되돌리기 버튼 포함)
├── board/                       # 보드 타일: buildBoardTiles(목록 만들기), upload(Life Hub에 올리기), vendor/schema.js(board 규격 검사 복사본)
├── lib/
│   ├── appState.js              # 저장 형식 v2, 정규화, v1 → v2 이전, 기본 목록 업그레이드, 백업 파일
│   ├── catalogSnapshot.js       # 기본 목록의 스냅숏·digest (npm run catalog:snapshot)
│   └── localStore.js            # localStorage 읽기/쓰기
├── utils/
│   ├── achievementEvaluator.js  # 업적 계산 엔진
│   ├── achievementText.js       # 조건·진행도 문구
│   ├── units.js / dates.js      # 단위 환산·값 입력 해석, 날짜·기간·연속 기록
│   └── suggestions.js           # 기록할 때 보여 줄 추천 태그·단위
├── data/
│   ├── categories.js            # 기본 카테고리 99개
│   ├── achievements.js          # 기본 업적 목록 (catalog/ 의 분야별 파일을 모음)
│   ├── catalog/                 # 분야별 기본 업적 1410개
│   └── catalogHistory.js        # 예전 기본 목록의 스냅숏, 목록 버전
├── pages/                       # 홈(Dashboard), 기록(RecordHub), 업적(AchievementManagement), 진열장(AchievementShowcase)
└── components/                  # 화면 조각 (Modal, Medal, AchievementCard, RecordEditorModal …)
```

화면 스타일은 Tailwind CSS와 `src/index.css`의 색상 토큰(라이트/다크)으로 관리합니다.
글꼴은 [Pretendard](https://github.com/orioncactus/pretendard)(SIL OFL 1.1)를 CDN으로 불러오고, 오프라인에서는 서비스 워커 캐시를 씁니다.
